# Core capability index

Keyword index for the enzUI capabilities that are not widgets: the models,
reducers, geometry resolvers and policy layers an app calls directly.
`docs/widgets.md` is the sibling index for widgets.

This page is the `enzui-core` crate documentation
(`crates/enzui-core/src/capability_index.md`); `docs/core-capabilities.md` is
generated from it with every link pointing at a source file.
The keyword check in `crates/enzui-core/tests/capability_index.rs` requires a
non-module-name search term for each indexed core target it recognizes.

## Finding a core capability by keyword

For **avatar export**, **image encoding**, **JPEG matte**, **metadata removal**
or **save a cropped image**, enable `enzui-resources/image-ops` and use
[`ImageOperations`](../crates/enzui-resources/src/image_ops.rs). The app owns
its bounded worker pool; results carry the submitted generation and encoded bytes.
PNG, JPEG with an explicit matte, and lossless WebP are supported. Metadata is
cleared by default; explicit retention normalizes orientation and output size,
with a separate GPS choice. `EncodedImageResult::publish_new` uses atomic
no-clobber publication; pickers and confirmation remain app-owned.

For **shell activity**, **background-work publication**, **activity publisher**
or **broker job status**, use the separate renderer-independent
[`enzui-activity`](../crates/enzui-activity/README.md) SDK. It publishes
bounded, coalesced producer status over the enzui activity v1 socket without socket I/O
on UI threads. This is separate from the in-app `operation_activity` model below.
For **dock progress**, **launcher progress**, **taskbar progress** or
**`com.canonical.Unity.LauncherEntry`**, the same `Publisher::new` emits the
standard LauncherEntry signal whenever the activity socket is unreachable (other
desktops, Flatpak); see the SDK's *Dock progress elsewhere* section.
For **native window tags** and **per-window background activity identity**, see
that SDK's native identity section and `iced::window::set_toplevel_tag`.

For **headless agent handlers**, **background app event loop**, **installed app
catalog** or **package manifest**, use `enzui-agent::center` with
`central-connector`. `CenterHost::spawn_headless` and `poll_headless` deliver the
same typed registry commands and cancellation notices without iced; polling wakes
at live deadlines. `center::installed::manifest` exports the exact v2 registration
with the schema-1 fixed-unit wrapper. Export only handlers implemented by the
app's background mode.

For the **center wire protocol**, **center framing**, **center handshake
proof** or **daemon and app share the protocol**, depend on
`enzui-center-protocol`: frames, message and credential types, and the HMAC
proofs, with no socket or I/O policy. `enzui-agent::center::{protocol,
wire}` re-export it; its `daemon_golden` test pins frames and proofs the
daemon wrote.

For an **agent background mode**, **`--agent-background`**, **windowless app**,
**idle exit** or **present the window over background state**, enable
`enzui-agent/background` and use `center::background::run`. It drives the
app's own reducer and subscriptions on a headless executor (no display, renderer
or window), submits reducer tasks to a `TaskHost`, and returns the same state
when the app asks to present, exits or stays idle for the timeout.
`LaunchMode::from_args` classifies `--agent-background` and
`--export-agent-manifest`. For the package's **systemd user unit** or **app
sandbox**, `center::installed::unit` renders `enzui-agent-APP_ID.service` with
the app's `UnitSandbox`: a worker-only unit is hardened and confined
(network, home, own XDG directories), and a `desktop` unit, which runs the
app's window, is unsandboxed so what the app opens is not confined. For **D-Bus activation**, **DBusActivatable**, **one unit for
window and worker** or **launch the installed app in its unit**,
`center::installed::dbus_service` renders the session service file that makes
`APP_ID` activatable through that unit (installed as
`dbus-1/services/APP_ID.service`, beside a desktop entry with
`DBusActivatable=true`), and `ApplicationService::activate_installed` delivers
a launch through it with a bounded deadline. For **single-instance agent
apps**, **forward a desktop launch to the agent worker** or **present the
window over background state**, the shared glue is `enzui-agent-app`:
`AgentProcess` (the per-process state beside the domain model),
`claim_desktop` (the installed executable hands its launch to the bus once and
exits; other builds converge only when provisioned) / `claim_background` (no
credential needed: without one the worker serves desktop launches and refuses
agents), `print_manifest`, `deadline_instant` and `disposition` (a worker
exits on broker EOF once nothing is live).

For **user review before an external effect**, **`ui.user_review`**, **send only
after the person confirms**, **review handle** or **awaiting_user**, use
`center::review::ReviewBook` and `USER_REVIEW_CAPABILITY`. A review is scoped to
an account, bound to the content revision shown, committed once from the
person's own control and superseded by new content; status reads in another
scope find nothing.

For **v3 broker authentication** and **commit-report capability proofs**, use
`center::auth::authenticate_v3`. This low-level driver verifies the exact ordered
capabilities before registration. `CentralConnector` tries v3 first and reconnects
once with v2 only after an empty unsupported-auth closure, within its original
total setup deadline. Rejection, malformed/truncated frames and proof/capability
failures never downgrade. `negotiated_wire_version` reports the registered
connection's version; report transport and durable acknowledgements remain pending.

For **background reducer tasks**, **keep work through GUI promotion** or
**idle exit with pending messages**, enable `enzui-agent/task-host` and use
`center::task_host::TaskHost`. It owns one renderer-free executor and the same
bounded message queue in both delivery modes. Keep task abort handles beside live
call references for cancellation. `has_work` includes submitted streams and
unconsumed results; combine it with windows, live calls and app-owned operations
before exiting. Font, image and system actions are deferred for the GUI:
`take_deferred` hands them to the window runtime, and the waiting streams resume
there. Window, clipboard, backend, exit and synthetic-event actions are refused
and abort their submitted stream.

For **single-instance agent apps**, **reuse a foreground process** or **background
activation without presenting a window**, use
[`ApplicationService::connect_or_forward`](../crates/enzui-core/src/activation/dbus.rs)
with `application-dbus`. The first launch owns the desktop app endpoint; later
background launches reuse it quietly, while explicit desktop intents are forwarded
to its current unique bus owner. Keep that endpoint with the shared domain state
until final exit. This transport does not itself open windows or approve effects.

Use [the widget catalog](widgets.md) for visual components and the tables
below for application models, policies and platform integration boundaries.
Search by intent, such as `hotkey`, `range select`, or `remember window size`.

**Localization and time formatting**
[`localization`](../crates/enzui-core/src/localization/mod.rs) supplies Fluent app/widget catalogs, language negotiation,
scoped defaults, CLDR number/date/time formatting and locale direction.
[`time_of_day`](../crates/enzui-core/src/time_of_day.rs) supplies an explicit reversible grammar for editable time fields.
See [the localization guide](localization.md) for language switching and translator resources.

**Current local civil time lives in [`local_time`](../crates/enzui-core/src/local_time.rs).** Search `local clock`,
`local time`, `wall clock`, `system clock`, `timezone`, or `daylight saving`.
The API returns a typed [`civil_date::Date`](../crates/enzui-core/src/civil_date.rs) and minute-of-day after one
`SystemTime` sample. Its Linux `localtime_r` boundary returns typed failures;
unsupported platforms and failed or out-of-range conversions never become UTC.
Apps must not parse file-browser display text, mutate process-global `TZ`, or
spawn a shell helper to acquire local time.

The name is unique per *call*, not per process: a `<file>.tmp-<pid>` name collides between two concurrent writers in one process, and the unlink-and-retry it forces destroys the other writer's live temp so the survivor's rename publishes a foreign blob. A collision here is therefore hostile, never stale, and is **refused**. Publication and cleanup are bound to the *inode* the stage exclusively created, not to the staging name: a name substituted in the window between the durability barrier and the rename is refused (the old destination survives, the substitute is left untouched) instead of being published or unlinked. Do not hand-roll a temp path, do not `File::create` then `set_permissions` (world-readable window), and do not stage under `/tmp` - a cross-device `rename` is not atomic. For Linux no-clobber publication, [`tempstage::link_new_by_identity`](../crates/enzui-security/src/tempstage.rs) hard-links the held descriptor's inode through `/proc/self/fd` and returns `EEXIST` rather than replacing a destination; [`tempstage::verify_path_names_file`](../crates/enzui-security/src/tempstage.rs) revalidates the reported name after a blocking durability barrier. Both fail closed where identity-bound publication or verification is unavailable. Any *other* exclusive-create-then-clean-up flow (a backup copy, a scratch export) that must unlink what it created should call [`tempstage::remove_if_path_names_file`](../crates/enzui-security/src/tempstage.rs) with the descriptor still open, rather than `std::fs::remove_file` on the name: a name replaced during the blocking copy/`fsync` window otherwise costs a foreign inode, or the target of a planted symlink. Exact-name diagnostics under a retained private root compose [`SecureRoot::create_entry_private`](../crates/enzui-security/src/secure_dir.rs), [`SecureRoot::entry_identity`](../crates/enzui-security/src/secure_dir.rs) and [`SecureRoot::unlink_entry_if_identity`](../crates/enzui-security/src/secure_dir.rs): credentials are created `O_CREAT | O_EXCL | O_NOFOLLOW`, mode-normalized through the descriptor before the first byte, and cleaned through the retained parent; a filesystem Unix socket captures its entry identity after `bind(2)`, refuses a unique-name collision instead of unlinking it first, revalidates identity before pathname `chmod`, and cleans through the retained parent. The listener fd cannot identify that entry because its `fstat` reports a `sockfs` inode. [`DirectoryStage`](../crates/enzui-security/src/tempstage.rs) extends the same identity-bound contract to a private mode-`0700` directory beneath a retained [`SecureRoot`](../crates/enzui-security/src/secure_dir.rs): its Drop opens descendants descriptor-relatively without following symlinks and, per entry, unlinks only while the current `fstatat` identity through the parent descriptor still equals the identity retained at creation - the same strict `fstatat`→`unlinkat` narrowing [`SecureRoot::unlink_entry_if_identity`](../crates/enzui-security/src/secure_dir.rs) documents (POSIX has no unlink-by-inode). A subtree whose identity changed after retention is not traversed, is not removed, and its owned ancestor is retained. Cleanup also refuses to descend beyond 64 levels or observe more than 65 536 entries per Drop (same fail-closed retention), so a same-uid actor with write access to the stage cannot escape identity into a replacement path or drive Drop to blow the stack. [`DirectoryStage::try_cleanup`](../crates/enzui-security/src/tempstage.rs) exposes the same cleanup as an observable, retryable `io::Result<bool>`: `Ok(true)` only when every descendant and the root name were removed, `Ok(false)` when identity substitution, policy drift, or a cleanup bound leaves anything retained, `Err` for a distinguishable descriptor/I/O failure during the final root removal. On `false` or `Err` all descriptors and identity remain live so the caller can retry; after `true`, `Drop` is an inert no-op. Used by `enzui_resources::service_download` for extractor stages. [`SecureRoot::create_anonymous_file`](../crates/enzui-security/src/secure_dir.rs) creates a private read/write Linux `O_TMPFILE` through the retained directory descriptor, with close-on-exec ownership, no directory entry and no named fallback; its last descriptor close reclaims the inode even after a crash. |
